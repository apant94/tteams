# Team

**Team** — небольшая веб-платформа для общения мастера со своими клиентами.

Клиент получает личный чат, в котором может написать мастеру, узнать статус заказа и получить готовые файлы. Мастер работает со всеми обращениями в одном интерфейсе и видит отдельный диалог с каждым клиентом.

> Первая версия проекта ориентирована на одного мастера и несколько десятков клиентов.

## Возможности MVP

### Для клиента

- вход по персональному паролю;
- один личный чат с мастером;
- отправка и получение текстовых сообщений;
- просмотр статуса заказа;
- получение готовых файлов от мастера.

Клиент видит только свой диалог и свои данные.

### Для мастера

- авторизация в панели мастера;
- список клиентов и их чатов;
- просмотр истории переписки;
- отправка сообщений и файлов;
- изменение статуса заказа;
- создание приглашений для новых клиентов.

Мастер видит все диалоги, но каждый клиент представлен отдельным чатом.

## Статусы заказа

В первой версии достаточно двух статусов:

- `В работе`;
- `Готово`.

При развитии проекта можно добавить этапы обработки, сроки и уведомления.

## Технологии

Проект планируется реализовать без frontend-фреймворков:

- PHP 8.2+;
- HTML5;
- CSS3;
- обычный JavaScript;
- SQLite;
- собственная минимальная автозагрузка без сторонних зависимостей;
- простые автоматические тесты на PHP и Bash.

Новые сообщения загружаются с помощью polling: браузер периодически обращается к API через `fetch`. Для небольшого количества пользователей WebSocket, Redis, React и Node.js на старте не требуются.

## Как работает платформа

1. Мастер приглашает клиента в сервис.
2. Клиент входит по выданному ему персональному паролю.
3. После входа клиент попадает в единственный доступный ему чат.
4. Мастер видит клиента в общем списке диалогов.
5. Сообщения обновляются автоматически раз в несколько секунд.
6. После завершения работы мастер меняет статус заказа и отправляет готовые файлы.

В первой версии SMS и регистрация не нужны: мастер заранее создаёт клиента и передаёт ему пароль. В базе хранится только безопасный хэш пароля.

## Основные сущности

- **User** — пользователь с ролью `admin` или `client`;
- **Conversation** — личный диалог клиента с мастером;
- **Message** — сообщение в диалоге;
- **Order** — заказ клиента и его текущий статус;
- **Invitation** — одноразовое приглашение клиента;
- **Attachment** — файл, отправленный в чате.

## Безопасность

Безопасность обязательна даже для небольшой закрытой платформы:

- запросы к базе выполняются через PDO и prepared statements;
- пароли хэшируются через `password_hash()` и проверяются через `password_verify()`;
- коды и приглашения создаются с использованием `random_bytes()`;
- после входа идентификатор сессии обновляется через `session_regenerate_id(true)`;
- cookies используют флаги `HttpOnly`, `Secure` и `SameSite`;
- все изменяющие запросы защищаются CSRF-токеном;
- пользовательский текст экранируется через `htmlspecialchars()`;
- каждый API-запрос проверяет авторизацию, роль и доступ к конкретному чату;
- попытки входа ограничиваются по частоте;
- загружаемые файлы проверяются по типу и размеру и хранятся вне публичной директории.

Клиент никогда не должен получать доступ к чужому чату, даже если вручную изменит идентификатор в URL или API-запросе.

## Локальный запуск

Для просмотра первого прототипа страницы входа:

```bash
php -S localhost:8000 -t public
```

После запуска страница доступна по адресу `http://localhost:8000`.

Подготовка локальной SQLite-базы и двух демо-пользователей:

```bash
php bin/database-migrate.php
php bin/database-seed-demo.php
```

Файл базы создаётся в `storage/app.sqlite` и не добавляется в Git.

Демо-пароли предназначены только для локальной разработки:

- администратор: `admin-demo`;
- клиент: `client-demo`.

Проверка текущего прототипа:

```bash
bash tests/run.sh
```
